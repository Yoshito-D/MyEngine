# 共通UIの使い方

## サンプルを開く

エディターのシーン一覧から `UISample` を開き、Playを押す。
Gameビュー内をクリックして入力先を選ぶ。

- マウス：ボタンのクリック、スライダーのクリック／ドラッグ、トグルの切り替え。
- キーボード：上下またはW／Sで選択、Spaceで決定、Escapeで戻る。Tab／Shift+Tabでも移動できる。
- パッド：十字キーまたは左スティックで選択、Aで決定、Bで戻る。
- スライダー：左右入力で値を変更する。

「Open overlay」で上の画面を開くと、Gameの時計だけが停止する。
UIの時計、上画面の文字の浮遊、UI操作音は継続する。
Closeまたは戻る入力で下の画面へ戻る。
画面の表示・終了と、部品の選択・決定にもアニメーションが付いている。

## エディターで作る

1. 作成メニューの「共通UI → 画面」でCanvasとScreenを持つルートを作る。
2. 親を選択し、「共通UI」からボタン・スライダー・トグル・ラベルを作る。
3. UI矩形の `elementKey` を画面内で一意に設定する。
4. `position`、`size`、`anchor`、`pivot` で配置する。単位はUIピクセル。
5. 親へUI自動整列を追加すると、子を固定サイズのまま縦／横に並べられる。
6. 画面ルートを選択し、共通UIメニューでアセット名を入力して「選択画面を保存」を実行する。
7. 「UI画面を配置」またはアセットブラウザーから、別シーンへ展開配置する。

画面アセットは `Resources/game/ui/*.json` に保存する。
展開配置したObjectはシーン自身のデータとなり、元アセットの後の変更は自動反映しない。
画面ルートの複製・削除とアセットの配置は、子孫を含めてUndo／Redoできる。

Canvasの既定寸法は1280×720。左上原点・右向きX・下向きYで、描画先へ一様拡縮する。
UI矩形が配置の基準で、Transformの位置・回転・スケールは追加の演出として合成される。
ラベルはUITextのスタイルでフォント・文字サイズ・折り返し幅を設定する。
UIグループの表示状態と透明度は子孫へ継承され、保存済みの文字色を変更しない。

## UIアニメーションを作る

新規の画面には表示・非表示の演出、ボタン・スライダー・トグルには選択・決定の演出が付く。
既存の共通UIでは、コンポーネント追加から「UIアニメーション」を追加する。
「画面の演出を設定」「ボタンの演出を設定」で、関連するタイミングをまとめて設定できる。
この二つの操作は、そのコンポーネントの既存の演出設定を置き換える。

1. インスペクターの「タイミング」で、表示・非表示・選択／ホバー・選択解除・決定・常時を選ぶ。
2. プリセットからフェード、スライド、ポップ、強調、押し込み、脈動、浮遊、揺れ、回転を選ぶ。
3. 再生時間・開始待機・補間を調整する。「選択・ホバー」と「常時」はループ／往復にも対応する。
4. 「キーフレーム」で時刻、移動、拡縮倍率、回転、不透明度を編集する。中間キーも追加できる。
5. Editモードの「プレビューを再生」で確認する。再生位置のスライダーで任意の時刻へ移動し、
   「プレビュー解除」で元の配置に戻す。Play中の実行アニメーションはUI更新に従う。

時刻は秒、移動はUIピクセル、回転の編集は度。保存時の回転単位はrad。
表示／非表示、選択／選択解除、決定、常時の演出は同時に重ねられる。
選択演出を切り替える際は現在値からつなぎ、決定演出は終了時に基準値へ戻る。
選択解除の設定が無効でも、選択による変形は短時間で基準値へ戻る。

演出は要素の中心を基準に適用する。親に付けると子孫も一緒に動き、文字とSpriteは同じ変換を使う。
マウス判定にも同じ変換を使うため、拡縮・回転・移動中も見た位置で操作できる。
元のUI矩形・Transform・文字色・マテリアルを書き換えず、設定だけをシーン／画面アセットに保存する。
プレビューと再生位置は保存せず、設定編集は通常のインスペクターのUndo／Redoに対応する。
Canvas外の従来UIでは、既存のTween／Fadeを引き続き使用する。

C++から任意のタイミングを再生する場合は、対象部品のコンポーネントを取得する。

```cpp
if (auto* animation = object->GetComponent<GameEngine::UIAnimationComponent>()) {
   animation->Play(GameEngine::UIAnimationEvent::Click);
}
```

## C++で操作を接続する

ゲーム固有Componentの `OnSceneLoaded` など、全Objectの復元後に接続する。
部品からゲームの状態を直接参照させず、画面を使う側が処理を登録する。

```cpp
auto& ui = world.GetUI();
const std::string rootId = ui.InstantiateScreen("game/ui/MyScreen.json");

if (auto* object = ui.FindElement(rootId, "confirm")) {
   auto* button = object->GetComponent<GameEngine::UIButtonComponent>();
   button->SetOnClick([this]() { ApplySelection(); });
}

ui.Push(rootId);
```

スライダーとトグルは `SetOnValueChanged` で値の変更を受け取る。
`SetValue(value, false)` は通知せずに実行値を設定する。
Inspectorの `value` は初期値であり、実行中の値とコールバックは保存しない。
コールバックが捕捉する対象は画面の利用中に生存させ、先に破棄する場合は登録を解除する。
シーン破棄時にはUI実行系が全登録を解除する。

## 画面スタックと時間

- `Push(rootId)`：シーン内の画面を開く。同じ画面の二重Pushは拒否し、終了演出中なら閉じる処理を取り消す。
- `Pop()`：上の画面の終了演出を開始し、完了後に閉じる。Objectと選択状態は保持する。
- `Clear()`：画面スタックとコールバックを解除する。Objectと配置順は保持する。
- `RemoveScreen(rootId)`：画面と全子孫を削除する。
- `drawBelow`：下の画面を描画するか。
- `blocksBelowInput`：下の画面とゲームへの入力を遮断するか。
- `pausesGameplay`：スタックにある間、ゲーム進行を停止するか。
- `openOnStart`：シーンの初期化時に画面を開くか。

UIは実時間で更新し、ゲーム内ポーズ中も操作・演出を続ける。
画面変更APIは要求を記録し、フレーム開始またはUI入力の配送終了で確定する。
入力コールバック内でClearや削除を要求した場合、その入力の残りの配送を打ち切る。
終了演出中は画面の操作を受け付けず、終了するまでゲーム停止と入力遮断の方針を維持する。
演出完了は次のフレーム開始で反映する。描画やエディターの矩形選択は開閉状態を変更しない。
終了演出がない場合は直ちに閉じる。非表示・無効化・削除された演出の完了は待たない。
エディターのPauseはUIも停止し、StepはUIを一度進める。
ゲーム内ポーズ中のStepではゲームを進めない。
ゲーム内ポーズではBGM・SEを停止し、UI音声を継続する。

新しいUI部品は入力を個別にポーリングしない。
`UISystem` が入力を配送し、画面変更は配送終了後に反映する。
Sceneビューは配置・選択用で、再生中のUI操作はGameビューで行う。

## 実装の責務と拡張

- `UISystem`：画面状態、フォーカス、入力配送、画面変更要求を管理する。
- `UILayoutSolver`：読み取り専用のシーンと画面順から、独立した矩形配列を計算する。
- `UIScreenAssetSerializer`：UIアセットに対応する型を検証し、ファイルを入出力する。
- `SceneObjectStore`：Objectの所有と、階層の保存・復元・削除を担当する。

`UISystem::BeginFrame` は前フレームの完了と要求を反映し、入力を配送した後で停止方針を確定する。
ComponentのUI更新はSceneWorldで一度だけ行う。`BuildLayout` は更新や状態遷移を行わない。
描画・入力・編集はそれぞれ独立した配置結果を使い、座標変換の計算方法を共有する。

Undo／Redo用の階層スナップショットは全Component設定を保持する。
AudioSourceなど、UIアセットの対応範囲外のComponentが付いていても削除とUndoは利用できる。
UIアセットへの書き出しでは対応範囲を検証し、失敗理由を表示する。

独自の操作部品は `UIWidgetComponent` を継承し、通常のComponentファクトリへ登録する。
同じObjectへ接続できる操作部品は一つ。共通入力・描画は派生型を基底型として取得する。
`GetAdjustmentAxis` と `Adjust` で方向入力を消費し、`GetVisual` で色と値の表示割合を返す。
選択・決定とアニメーションの接続はUISystemが担当し、部品側はアニメーション型を参照しない。
